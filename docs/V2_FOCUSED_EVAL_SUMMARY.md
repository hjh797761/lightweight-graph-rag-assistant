# v2 Focused Evaluation Summary

本轮只做检索层评估，不调用 Kimi。目的不是证明答案生成能力，而是检查每个系统是否拿到了回答所需证据。

## 1. 总体结果

### 人工智能行业白皮书

| System | Key Point Hits | Hit Rate |
|---|---:|---:|
| Naive-single | 40/46 | 87.0% |
| Frozen-scoped | 42/46 | 91.3% |
| V2-scoped | 43/46 | 93.5% |

结论：白皮书这种主题链长、概念跨度大的材料，v2 有小幅但稳定优势。

### 贵州茅台年度报告

| System | Key Point Hits | Hit Rate |
|---|---:|---:|
| Naive-single | 31/46 | 67.4% |
| Frozen-scoped | 41/46 | 89.1% |
| V2-scoped | 44/46 | 95.7% |

结论：财报材料上，GraphRAG 明显优于 Naive；加入轻量相邻 chunk 补桥后，v2 在跨 chunk 表格数字 + 原因说明题上超过冻结版。

## 2. 最适合展示 v2 优势的题

### AIF01 算力瓶颈逻辑链

结果：

- Naive-single: 6/8
- Frozen-scoped: 8/8
- V2-scoped: 8/8

Naive 漏掉 `A100` 和 `CUDA`。这题适合展示 GraphRAG 对跨段证据链的覆盖能力。

### AIF02 监管沙盒演化

结果：

- Naive-single: 6/6
- Frozen-scoped: 5/6
- V2-scoped: 6/6

这题是 v2 相对冻结版的优势题。它要求把金融科技监管、Sandbox 流程和 AI 治理作用串起来，v2 的 topic scope 更容易保住完整主题链。

### MTF01 财务表格 + 原因说明

结果：

- Naive-single: 3/9
- Frozen-scoped: 9/9
- V2-scoped: 9/9

这题非常适合展示 GraphRAG 相对普通 RAG 的优势。普通 BM25 命中原因说明，但漏了大量表格数字；GraphRAG 能把表格数字和原因说明一起拿到。

### MTF04 ESG + 分红 + 回购三类证据

结果：

- Naive-single: 4/7
- Frozen-scoped: 7/7
- V2-scoped: 7/7

这题适合展示多维证据覆盖。Naive 漏掉分红历史新高、60 亿元回购、第二轮回购。

## 3. 不适合用来展示 v2 优势的题

### AIF05 金融基础设施多技术组合

三类系统都是 8/8。虽然题目看起来复杂，但关键证据集中度高，不容易拉开差距。

三类系统都是 10/10。这是 sanity check 题，不是优势题。

## 4. v2 暴露出的劣势

### MTF02 经营现金流下降与财务公司

结果：

- Naive-single: 3/6
- Frozen-scoped: 3/6
- V2-scoped: 6/6

补桥前，三者都命中了原因，但都漏了现金流表中的三个数字：

- `61,522,204,989.35`
- `92,463,692,168.43`
- `-33.46`

原因：金额表在 `chunk_000012`，原因说明在相邻的 `chunk_000013`。v2 命中了原因说明 chunk，但没有把前一个表格 chunk 一起保留下来。

已修补：做通用的相邻 chunk 补桥。当命中的 chunk 是表格原因说明、且问题同时要求金额/同比/本期数/上期数时，自动补入同文档相邻的前后 chunk。这个改法不是财报特例，也适用于白皮书表格、制度文件分栏、论文公式说明等跨 chunk 证据。

### MTF06 核心竞争力 + 2026 计划 + 风险

结果：

- Naive-single: 5/7
- Frozen-scoped: 5/7
- V2-scoped: 5/7

三者都漏了 `宏观经济风险` 和 `环境保护风险`。原因是题目横跨核心竞争力、经营计划、风险提示三个很远的章节，当前 top-k 更偏向前两个主题。

建议修补：如果问题显式出现“风险/风险提示/未来经营风险”，候选池中应保留至少一个风险章节候选。更通用的说法是按问题中的并列维度做 coverage，而不是只按整体相似度选 top-k。

## 5. 建议给老师展示的题目组合

推荐 4 道主展示题：

- `AIF01`：展示跨段概念链，说明 GraphRAG 不只是关键词匹配。
- `AIF02`：展示 v2 topic scope 相对冻结版的改进。
- `MTF01`：展示表格数字 + 原因说明的结构化检索优势。
- `MTF04`：展示多维证据覆盖，普通 RAG 会漏证据。

保留 2 道诚实的边界题：

- `MTF02`：说明当前系统仍存在跨 chunk 表格补桥问题，后续可用相邻 chunk 补桥修复。
- `AIF04` 或 `MTF03`：说明单点集中证据题上普通 RAG 也能做好，我们不夸大 GraphRAG。

## 6. 下一步代码修补优先级

1. 保留本次测评脚本的格式归一化修复。
2. 保留 v2 的通用相邻 chunk 补桥，只在问题和候选 chunk 都显示跨表格/原因说明需求时触发。
3. 下一步再考虑增加并列维度 coverage：当问题出现“分别、同时、从 A/B/C、三类证据”等结构时，最终 top-k 尽量覆盖每个维度。
4. 不建议继续堆财报专用词表。
